# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A self-hosted **MCP aggregator gateway**: one public MCP endpoint (`/mcp`, Streamable
HTTP) in front of any number of backend MCP servers. It has two independent OAuth legs:

- **Client-facing** (`oauth_server.py`): the gateway *is* a spec-compliant OAuth 2.1
  authorization server for MCP clients — DCR (RFC 7591), CIMD, PKCE S256, RFC 8414/9728
  metadata.
- **Backend-facing** (`upstream.py`): the gateway *is* an OAuth client against upstream
  MCP servers, using its own credentials.

Adding a backend is config-only (`config.yaml`); no code changes.

## Commands

```bash
uv venv && uv pip install -e ".[dev]"     # or: pip install -e ".[dev]"
(cd ui && npm install && npm run build)   # build the Svelte UI — see gotcha below
pytest                                    # full suite, incl. e2e OAuth flows over HTTP
pytest tests/test_oauth_flow.py::test_name -x    # single test
ruff check .                              # line-length 100, target py311; enforced in CI
mcp-gateway run -c config.yaml --log-level debug
```

`MCP_GATEWAY_LOG_LEVEL` (`debug`/`info`/…) sets the level outside Docker too;
`--log-level` takes precedence.

The tree is lint-clean but **not** `ruff format`-clean, and CI only runs `ruff check`.
Don't run `ruff format .` across the repo as a drive-by — it touches 13 files and buries
whatever you were actually changing.

CLI subcommands: `run`, `check` (validate config and exit), `hash-password`,
`migrate` (apply migrations without starting the server), `rotate-key
--old-key-file … --new-key-file …`.

### Tests

`pytest` runs with `asyncio_mode = "auto"` — async tests need no marker. `conftest.py`
provides `run_server` (real uvicorn in a background thread), a `gateway` fixture, and
`register_client` / `obtain_tokens` helpers that drive a complete
authorize → login → consent → token exchange over real HTTP. Tests spin up genuine
gateways, including a second gateway instance acting as an OAuth-protected upstream —
they are not mock-based, so a change to the OAuth wire format shows up as a test failure.

**Gotcha: build the UI before running pytest.** `tests/test_ui_static.py` serves the
built Svelte app from `src/mcp_gateway/static/ui/`; without `npm run build` it fails.
CI does the same (`.github/workflows/tests.yml`).

### Adding a migration

There is no SQLAlchemy ORM layer — migrations are hand-written DDL, never autogenerated.
`alembic.ini` at the repo root exists only for authoring; the gateway builds its own
Alembic config in code (`db_migrations.py`) so the DB path comes from
`storage.path` at runtime and `:memory:` databases migrate against the caller's open
connection.

```bash
alembic -x db-path=/tmp/dev.db revision -m "describe the change"
alembic -x db-path=/tmp/dev.db upgrade head
```

The schema predates Alembic adoption, so a migration altering an existing table must
guard itself with an existence check — follow
`migrations/versions/0002_session_revocation_and_client_ttl.py`. Add a regression test
in `tests/test_db_migrations.py`.

## Architecture

Request flow, root to leaf:

- `app.py::create_app` assembles everything: opens `Storage`, builds
  `GatewayOAuthProvider` + `BackendManager` + one `Client` per enabled backend, builds
  the FastMCP server, and mounts `mcp.http_app(path="/mcp")` **as a catch-all at `/`**.
  So `/mcp`, `/authorize`, `/token`, `/register`, `/revoke`, `/.well-known/*` are all
  served by the mounted FastMCP app; only `/auth/api/*`, `/oauth/*`, `/ui/*`, `/healthz`
  are explicit FastAPI routes in `web.py`. If a route seems missing, it's in the mount.
- `gateway.py` mounts each backend as a live FastMCP proxy under its namespace, so
  backend `github`'s `create_issue` becomes `github_create_issue`. A down or
  not-yet-connected backend only removes its own tools.
- `oauth_server.py` builds on the MCP SDK's AS handlers and FastMCP's CIMD manager; the
  gateway adds SQLite persistence, the login/consent transaction flow, and token
  issuance/rotation policy. `authorize` parks the request as a transaction and redirects
  to `/ui/authorize?txn=…`; the Svelte UI drives login/consent through `web.py`'s JSON
  API and finally calls `complete_authorization`.
- `upstream.py` uses the official SDK `OAuthClientProvider` with `DbTokenStorage`.
  OAuth backends are connected interactively **once** via `/oauth/connect/<backend>` in a
  browser; MCP traffic never triggers an interactive flow on its own. `ConnectFlow` state
  is in-memory.
- `storage.py` is a single serialized SQLite connection, no ORM. Envelope encryption: the
  operator's `encryption_key` is a KEK that only wraps a generated DEK, so `rotate-key`
  re-wraps ~32 bytes instead of re-encrypting the database. Tokens and auth codes are
  stored as SHA-256 hashes.
- `ui/` is a Svelte 5 + Vite SPA. `npm run build` writes into
  `src/mcp_gateway/static/ui/` (overridable via `VITE_OUT_DIR`, which the Dockerfile
  uses). `npm run dev` proxies `/auth/api` and `/oauth` to `localhost:8000`.

## Invariants and conventions to preserve

- **No token passthrough.** The gateway token issued to an MCP client must never reach a
  backend. `gateway.py` sets `transport.forward_incoming_headers = False` and *raises at
  startup* if that attribute is missing — a fastmcp upgrade that renames it must be
  handled, never worked around by deleting the check.
- **Single-instance by design.** SQLite, in-memory connect flows, and in-memory rate
  limiting all assume one process. Don't introduce work that only makes sense across
  replicas without saying so.
- **Logging is configured in `mcp_gateway/__init__.py`**, before any submodule and before
  fastmcp is imported (it syncs `FASTMCP_LOG_LEVEL`); `app.py` then strips fastmcp's own
  handler so all logs share one format. Keep that ordering. Never log credentials or
  tokens, at any level.
- `mask_error_details=True` on the FastMCP server and proxies: backend URLs and HTTP
  error bodies must not leak to MCP clients. Diagnose from server logs at `--log-level
  debug` instead.
- `app.state` is replaced with the typed `GatewayState` (`state.py`); read it via
  `get_state(request)`, and declare any new attribute there rather than stashing it
  loosely.
- Config values support `${ENV_VAR}` / `${ENV_VAR:-default}` expansion (`config.py`).

`README.md` carries the operator-facing detail (deployment, encryption-key handling,
endpoint table, hardening measures); `SECURITY-REVIEW.md` records the threat analysis.
